# Solar24 整体体验构想：从地球的一年，到一个地方的春天

日期：2026-09-18。状态：设计提案，供讨论；不是已批准的文化正文或已经实现的产品功能。

依据：原始 PRD V0.2、当前架构与设计原则，以及本轮提出的“24 节气轮转、地球在宇宙中的位置、日历系统、先整体构思再实施立春”。保留原始 PRD。本提案建议扩展首期体验框架，具体替代关系在第 10 节说明。

配套：[可点击概念稿](solar24-world-calendar-concept.html)。概念稿用于体验结构和视觉评审，使用代码绘制的说明图，不含真实实时星历、农历换算或已审核文化正文。

## 1. 产品主张

**以二十四节气为一年中的文化坐标，让人从地球与太阳的关系，走到自己所在地方的生活。**

整体采用“年轮为中心，空间与生活向两侧展开”的结构。宇宙提供尺度，一年提供导航，日历连接今天，节气故事连接人。宏大感来自尺度之间可理解的关系和连续的视点变化。

核心问题：此刻，我们在一年中的什么位置？这个时间，在不同地方意味着什么？

### 四个尺度

| 尺度           | 用户的问题                         | 表达方式                                       | 深度                             |
| -------------- | ---------------------------------- | ---------------------------------------------- | -------------------------------- |
| 宇宙中的家园   | 地球处在怎样的空间关系中？         | 银河系—太阳系—地球的层级定位；太阳与地球关系图 | 先提供相对关系，宇宙全景后续增强 |
| 地球的一年     | 节气为何循环？                     | 24 节气年轮；可展开太阳视黄经与公转关系说明    | 主界面                           |
| 生活中的一天   | 今天是什么日子？离下一个节气多久？ | 公历、农历和节气的对照日历                     | 常用入口                         |
| 一个地方的生活 | 这个时间对人意味着什么？           | 立春故事、地域案例、来源、世界邀请             | 首个完整内容模块                 |

宇宙层级只表达可说明的相对位置，不声称地球有一个绝对“宇宙坐标”。银河定位不承担节气成因解释；太阳与地球的关系承担这一解释任务。

## 2. 主界面：可以反复回来的二十四节气年轮

桌面主画面由左侧一句引导、右侧大年轮、底部时间入口组成。外圈排列节气，中间显示所选节气与阅读入口。页面顶部仅保留年轮、宇宙、历日三个主要目的地；进入立春后显示返回年轮。

首次访问直接获得可操作的年轮。可以主动选择“从宇宙开始”，进入可跳过的引导。再次访问可回到上次位置，并一直提供“回到今天”。不强制观看片头，不把滚轮锁成电影播放器。

### 年轮的三个状态必须清晰分离

- **今天**：真实当前时刻的标记；在数据范围内才显示当前节气。
- **正在浏览**：用户点击的节气；例如九月仍可主动进入立春，不改变“今天”。
- **演示中**：用户主动播放一年变化；显式显示模拟时间，暂停后保留所选位置。

今天用小实心点，浏览用带文字的轮廓标记，三者不能仅靠颜色区分。日历换日、年轮选择、故事返回共用选择状态，浏览器后退应恢复选择。

### 交互

1. 点选任意节气，更新标题、序位、经审核的摘要及可用内容状态。
2. 拖动或左右按钮逐节气移动；另有完整文本列表供键盘、触摸及读屏使用。
3. 点击“进入立春”，保留年轮位置进入故事；返回时回到刚才的位置。
4. “播放一年”由用户启动，支持暂停和单步；未实现时不放假按钮。
5. 其余 23 项首期显示名称、顺序及真实状态，已有审定基础信息可展示。体验未开放时给出明确说明，避免看起来已完成。

### 圆环的科学含义

默认年轮是节气顺序和等角刻度的导航图，明确注明“节气顺序示意，非等长日期刻度”。环本身不画成带地球绕转的实际轨道。

可切换到“按日期看一年”：365/366 天按实际时间铺开，交节节点依据核验时刻定位；此时节气间距通常不相等。两种图必须各有标题和图例，切换时解释变化原因。

## 3. 宇宙视角：把镜头拉远，再带回日常

建议的叙事镜头：

**银河系中的太阳系 → 太阳与地球 → 地球公转与自转轴 → 从地球观察太阳的位置 → 24 节气 → 一个地方的立春。**

初期用三步手动切换的说明图替代长距离连续飞行。成熟版本可以将这些视图连接成短转场，但每一步都有标题、暂停/跳过和静态等价内容。

### 两种观察视角

| 视角           | 显示什么                                     | 需要避免的误解                                     |
| -------------- | -------------------------------------------- | -------------------------------------------------- |
| 从太阳系看地球 | 地球公转、自转轴方向、日照关系；注明观察方向 | 四季不能归因于日地距离远近；轴倾不造成节气定义本身 |
| 从地球看太阳   | 太阳沿黄道的视位置；24 节气的现代角度定义    | 这是观察视角，不是声称太阳绕地球公转               |

从黄道北侧俯视时，公转方向与屏幕导航的顺时针排布可能不同。不得将顺时针的目录动画直接当公转动画。切换视角需标参照系；地球的日心位置与太阳的地心黄经不能使用同一个角度直接标注。

公转示意的大小、距离和速度经过简化时必须明示。精确交节时刻采用经核验的数据，不由示意动画反推。介绍现代天文定义时与历史历法实践分层，不把今天的等角定义当作各历史时代完全相同的规则。

全球读者可以选择北/南半球观察差异，但中国传统四季编组保持其文化语境，不自动改写为用户所在地的气候。所在地、时区、语言是三个独立设置；切换英文不会改变时区或气象解释。

## 4. 日历系统：同一天的三种读法

日历是第二条常用入口，服务“今天、选一天、理解历法”。年轮与日历是同一时间状态的两种视图。

### 第一层：今天

展示公历日期、用户显示时区、对应中国农历日期、当前节气区间、下一交节时刻及进入故事的入口。当前节气区间在交节瞬间切换，而不是当日零点切换。

必须区分“交节发生的瞬间”和“这一节气至下一节气的时段”。页面可以说“处于某节气时段”，精确时间另行展开。

### 第二层：月历与年历

- 月历每格公历为主、农历为辅，交节日加文字标记；周起始日明确。
- 年历总览 24 个节点；选择节气定位到相应日期和故事入口。
- 首期支持一个明确标注的年份或经过验证的有限年份范围；超出范围显示不可用，不能套用固定日期。
- 日期选择默认“浏览该日”；日内有交节时显示具体时刻，不能把整天误当成同一节气。若需要选具体瞬间，应提供时间输入，或在“进入该节气”操作时直接定位到交节瞬间。
- 今天按钮恢复真实当前时刻；刷新、深链接和浏览器返回保留所选日期、节气和视图。

### 第三层：为什么有几套日期？

短图解说明太阳周年运动、月相与月份、阴阳合历的协调，以及立春和春节为何不固定重合。首期不展开完整置闰算法，不加入宜忌、八字或通用日程管理。月相如未接入可信数据，不绘制成似乎精确的当天月相。

### 时区与日期约定

交节是同一瞬间，不同时区可能落在不同日期。内部以 UTC 保存时刻，界面显示明确的 IANA 时区及本地时间。中国农历须固定并说明历法口径，例如使用北京时间计算的中国农历日期，同时清楚说明它与用户本地日期的配对方式；不能声称切换时区后存在一套自动变化的“当地中国农历”。

经核验的事件数据须记录来源、版本、支持年份、精度与时间基准。准确交节时刻不得用每年固定月日代替；没有可靠数据就只开放结构预览。

## 5. 切入立春：从一个刻度到具体生活

建议故事题眼：**春天，从哪里开始？** 以下为叙事结构，文化文案仍走原审核流程。

| 章节            | 体验                                        | 读者获得什么             |
| --------------- | ------------------------------------------- | ------------------------ |
| 01 时间的位置   | 年轮保留一个立春标记，展示相关太阳位置说明  | 知道立春是怎样的时间节点 |
| 02 两种春天     | 简短对照天文刻度与有地域范围的自然记录      | 理解当地入春另有条件     |
| 03 日历的关系   | 同年公历/农历/立春/春节对照，数据核验后启用 | 知道立春与春节不同       |
| 04 一个地方的人 | 从九华立春祭或石阡说春中选择一个已审案例    | 认识具体地点、活动与时间 |
| 05 你的时间     | “这个时间，在你生活的地方意味着什么？”      | 从理解走向参与           |

首次完整故事控制在约 3–5 分钟；进一步证据和历法机制折叠展开。全局宇宙说明与模块故事相互链接，避免每个节气重复讲一遍天文学。

进入故事时采用轻短的视觉连续：年轮所选标记留在侧边，画面转换为浅色阅读页。未来具备获授权地方影像后，可以从地球位置过渡到那个地点；不把 AI 生成的风俗画面当纪录照片。

首版开放邀请可以引导查看贡献规范。真正的世界表达后续以作者自述、地点、关联理由、差异、许可和审核信息呈现，现有 AI 研究候选不作为社区投稿展示。

## 6. 视觉方向：从深空到日光下的阅读

选择叙事驱动的方法：用户像在一个可操作的时间展览中，从远处看地球，再走进地方生活。

- **尺度**：大年轮占桌面主要视觉区域，正文保持短行；宏大通过一个大主体建立，不堆叠数据面板。
- **节奏**：宇宙/年轮留出空间；日历采用整齐网格；故事段落以来源、图像、文字形成疏密变化。
- **气质依据**：空间观察需要安静、精确；文化解释需要可读、尊重；交互需要明确、可预期。中等字重，清楚的边线，低幅度动作。
- **文化表达**：书写感只用于少量中文标题；刻度、光照和地方资料承担主要识别。避免无来源的传统纹样堆叠。

### 色彩角色（提案值）

| 角色      | 值        | 用途                         |
| --------- | --------- | ---------------------------- |
| 空间背景  | `#111A1B` | 年轮和宇宙主画面             |
| 主文字    | `#F2F0E8` | 暗底文字                     |
| 辅助文字  | `#B7C5C0` | 暗底标注                     |
| 时间焦点  | `#D9B77A` | 当前选择、刻度重点，少量使用 |
| 生命/地点 | `#95C0A9` | 地球说明、立春辅助元素       |
| 阅读背景  | `#F5F3EC` | 故事与日历                   |
| 阅读正文  | `#233C35` | 浅底正文与按钮               |

四季色只在局部导航辅助使用，并始终保留文字；色彩是编辑设计，不代表全球环境实测。

字体：中文展示标题采用宋体/明朝体方向，正文使用系统无衬线；英文标题采用易读衬线，标签采用系统无衬线。概念稿使用本地系统字体，无外部字体请求。若正式引入字体，应核验简繁覆盖、英文配对、许可与体积。

桌面标题约 56–80px，手机 36–48px；正文 16–18px、行高 1.7–1.9；标注不少于 12px。间距以 8px 为基数。组件以细线、留白和字重区分，减少卡片嵌套。

动效：按钮反馈 120–180ms；视图转换约 300–500ms；尺度转换最多约 900ms且可跳过。正式的年轮拖动须有边界和吸附反馈；用户没有启动前不持续自转。减弱动效使用直接切换。

## 7. 小屏、无障碍与异常状态

手机以可触摸的简化轮盘加节气文本列表组合；不将 24 个细小标签压成无法点中的满圆。故事采用单列，日历点击区至少 44px。宇宙仍可查看说明图，3D不是必需路径。

当前选中、焦点、悬停和按压有形状或边线反馈；键盘可到达所有操作。年轮还需按钮/列表等价路径，不能仅能拖动。文字对比至少 4.5:1，关键非文字控件至少 3:1。

| 状态             | 处理                                               |
| ---------------- | -------------------------------------------------- |
| 天文数据加载     | 先显示可读页面与静态图，不提前显示推算数字         |
| 日期超范围       | 明示支持年份，并保留回到有效年份的操作             |
| 未审核故事       | 显示研究状态与已允许公开的入口信息，不输出待审断言 |
| 3D不可用或低性能 | 自动回到说明图，核心理解任务仍可完成               |
| 数据请求失败     | 保留选择、提供重试与可用静态内容，不制造倒计时     |
| 关闭动作/声音    | 不影响阅读、日期查阅和导航；声音默认关闭           |

公共首屏沿用现有 <200KB gzip JS 的设计目标；真实3D、纹理和音频按用户操作加载，另设预算实测。概念稿未实现无 JS 阅读，正式产品须另行交付静态内容路径；不能用它冒充可访问性验收。

## 8. 架构落点与实现边界

| 路径                       | 职责                                                    |
| -------------------------- | ------------------------------------------------------- |
| `apps/host/`               | 年轮、宇宙说明入口、日历视图、路由、日期与语言/时区偏好 |
| `modules/lichun/`          | 立春正文、地域故事、来源和模块内交互                    |
| `packages/protocol/`       | 时间事件与关联字段确有需要时的唯一契约定义              |
| `packages/module-runtime/` | 生命周期、偏好传播、必要的共享渲染能力                  |
| `data/`                    | 经审阅的公共事件数据或可重建索引；实施前决定版本和许可  |
| `knowledge-base/`          | 继续研究与人工审核，Host 永不直接导入                   |

日历和视点选择先留在 Host 的明确模块内。有第二个真实使用者再评估共享包，不提前创建宇宙引擎、calendar 包或场景平台。

建议状态模型：浏览视图、所选节气、所选日期/瞬间、真实当前时刻、播放状态、显示时区、语言、减弱动效。所选日期和瞬间语义分开；日期无需随语言切换改变。

契约变更仍需文档、schema 导出与消费者同步；导航/runtime 变更需完成 lint/test/build，并在构建后运行 E2E。涉及日期功能应验证跨年、闰年、时区导致交节跨日、交节前后、农历闰月和范围外行为。

## 9. 首期实施顺序与验收

### A. 全局结构原型

范围：Host 年轮、宇宙关系说明、日历布局、立春入口与返回。

验收：四个视图形成连续路径，所选节气可恢复；手机和键盘可操作；今天与浏览有区别；无需文化正文批准即可完成结构工作。

### B. 可信时间数据

范围：先选择一个或有限年份，经核验的 24 交节时刻与农历映射；公共数据契约、来源和权利记录；日历/年轮联动。

验收：交节按瞬间切换；时区和历法口径可见；极端日期测试通过；不通过未经审核的近似动画推导真实日历。

### C. 立春完整体验

范围：既有最小内容审核包、中文与英文、一个地方案例、来源、静态替代、日历中的立春/春节解释。

验收：真实事实与译文审核完成，5 位零背景读者的形成性测试中建议至少 4 位理解太阳刻度、当地季节差异、立春与春节的区别，以及能复述一个地方案例。

### D. 空间表现增强

依据原型测试决定是否加入实际3D地球、受控镜头、季节光照演示。验收依据是用户理解是否更好，以及性能和无障碍是否达标。宏大的总体结构在 A 已成立，不以高成本素材完成作为启动条件。

后续第二模块可选春分验证光照主题和公共组件，再按季节推广。世界表达以少量真实投稿试点。

## 10. 与现有立春 MVP 的关系

本提案保留立春为首个完整内容模块，扩展其外围框架：新增全局年轮、太阳—地球关系说明和有限年份日历。原简报“只做一个太阳位置互动”调整为“公共时间体验 + 一个立春故事”，其中日历数据成为明确的新工作包。

原有人工审核、来源、翻译与许可要求不变。当前提案并未将旧文档中的禁止3D自动替换为已经批准上线的完整3D工程；本轮授权是整体设计，真正实施时按明确的阶段范围交付。

## 11. 设计参考与本轮限制

- [NASA Eyes on the Solar System](https://eyes.nasa.gov/apps/solar-system/)：用于识别“可探索太阳系”这一产品参照。本轮读取到产品入口与描述，未声称完成其动态界面审计；正式设计可继续研究其尺度/视角控制。
- [NASA Earth Facts](https://science.nasa.gov/earth/facts/)：已读取官方入口，用于地球在太阳系中的相对位置背景。未将网页内容直接导入生产或设置人工审核状态。
