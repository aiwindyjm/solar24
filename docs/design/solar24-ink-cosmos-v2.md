## 2. 一个场景，三个观察尺度

**观天 → 察时 → 入春**。

观天：水墨星河中的太阳与地球关系，建立我们身处同一颗星球的视角。概念稿用代码绘制的空间关系图，大小、距离、轨道和星空均非精确模拟。后续完整叙事可逐级呈现银河系、太阳系、地球，当前并未实现真实银河定位或连续三维飞行。

察时：镜头聚焦太极节气盘，用户点选、前后切换或主动播放节气顺序。选择某节气时焦点刻度和太极意象转动，二十四节气标签保持可读。轮转是目录与艺术表达，不能用旋转角度推算实际日期或交节时刻。

入春：从同一场景展开立春故事，水墨背景、时间控制仍保留。第一章连接太阳位置，第二章解释立春与春节，第三章落到一个地方的迎春实践。正文在展开后阅读，首屏不承担百科介绍。

观天与察时的图形语义明确分开：太阳系图以太阳为物理关系中心，太极盘为文化导航与艺术构图。不能把太极当作真实天体、把八卦当作已证实天文学机制。

## 3. 太极与八卦的使用边界

太极采用经典黑白阴阳鱼的视觉母题，以墨边、干湿浓淡和细刻度构成层次。八个卦符逐爻绘制，保留卦名；当前排列为构图示意。

**本轮没有在现有知识库找到足以支持完整八卦—节气对应图的资料。** 没有进行外部文化考证，也未确定采用先天八卦、后天八卦或具体卦气传统。当前版本不标方位、不给每卦绑定三个节气、不暗示这张组合图是复原古图。页面保留“卦象排列非历法对应”的说明。

这允许先评审用户提出的视觉方向。若后续要让卦象层可解释、可导航，应单独研究具体传统、时代与原图来源，人工核验后再决定方位、次序和关系，避免把不同系统拼成貌似统一的古代历法。

四时编组表达本项目的中国传统节气导航，不代表全球同一时间都有相同季节。水墨星河、植物和太极旋转都属于原创艺术意象，不作为实测星图或物候证据。

## 4. 日历与年轮如何统一

底部常驻公历示例日期、12个月刻度和轮转控制。点击日期只展开一个小历页，仍能看见节气盘；选择月份或日子更新日期位置。故事内可随时展开历日。

概念稿尚未接入审核后的交节时刻与农历映射，因此公历选择与节气浏览保持独立，并在历页说明这一点。没有把示例2月1日伪装成立春日。

正式实现时共享同一个选中瞬间和时间视图，保留真实今天与探索时间的区别；公历、农历、节气按核验数据联动，遵循第一版中的时区和交节瞬间约定。日历不会再是一个脱离场景的独立导航目的地。

## 5. 视觉取向

- 背景为中性灰纸色 `#E8E8E8`；墨色 `#232323`，仅用朱红 `#933B31` 点出印记与所选节气。
- 以全幅星河、粗细不一的墨圈、密集细刻度和中心黑白互构建立远近关系。
- 中文标题采用系统楷体优先的回退字体，不加载外部字体。正式字体需另核字形覆盖与授权。
- 大字号纵排只用于标题与所选节气；功能控件保持清楚的横排文字。
- 画面中的星河和墨纹由代码绘制，不含无来源文化照片，也不伪装成地方纪实影像。
- 切换尺度约800–1000ms；关闭动效偏好下直接切换。持续轮转只在用户启动后运行，离开页面即停止。

## 6. 实现范围

本轮只新增 `docs/design/solar24-ink-cosmos-v2.html` 和本文；第一版保持原样。第二版是可直接在本地浏览的设计提案，不是完整太阳系模型、历法工具或文化发布版本。

实际支持：24节气选择、上一/下一节气、开始/暂停轮转、同场景尺度切换、历日展开/收起、2026公历月份与日期选择、立春故事结构展开、键盘操作和减弱动效。

后续需要：真实时间数据、完整宇宙尺度叙事、历法数据联动、太极/卦象来源研究、获审立春正文与地方影像。它们在设计上具有位置，但不能被计为已实现。
